# RelayDesk UI 稳定性标准 v1.0

更新日期：2026-11-18。适用于工作台新增及修改的界面。本文的“必须”是评审和验收要求，不表示存量界面已经全部符合。

## 1. 范围与交付物

1. 本文：视觉、布局、交互、异步状态与验收标准。
2. `app/ui/`：Button、IconButton、FormField、Dialog、Drawer、Popover、AsyncState；样式为 `app/ui/ui.css`，由根布局统一加载。
3. `/ui-lab`：独立组件验收页，包含模拟保存成功/失败、长记录、嵌套确认、详情抽屉与异步状态。页面公开但只有固定测试数据，不读取登录态、不连接业务 API；不是新的管理权限入口。

本轮建立底座，不替换旧界面、不调整业务 API 或数据库，也不宣称已解决所有历史 UI 问题。

## 2. 视觉基础

| 项目 | 基线 |
| --- | --- |
| 正文字号 | 14px；辅助信息 13px；模块标题 16px；弹窗标题 18px |
| 间距 | 4、8、12、16、24px；优先使用 `--rd-space-*` |
| 控件 | 默认最小高度 40px；桌面紧凑操作 32px，窄屏恢复 40px |
| 圆角 | 控件 6px，弹窗最大 8px |
| 颜色 | 中性表面与文字；绿色主操作、红色危险/错误、蓝色焦点，使用 `--rd-*` |
| 图标 | lucide-react；图标按钮必须有可访问名称和悬停提示 |

不能单靠颜色表达状态。键盘焦点必须可见，禁用与处理中必须有语义。字号不随视口宽度缩放，字间距为 0。旧界面字号应结合密度试点迁移，不机械全站替换。

## 3. 布局稳定性

- 每个页面或面板明确滚动容器；Grid/Flex 内容轨道使用 `minmax(0, 1fr)`、`min-width: 0` 和必要的 `min-height: 0`。
- 文本换行或省略必须明确；长无空格标识、错误信息不能撑破页面。不得用根节点横向裁剪隐藏布局错误。
- 图片指定尺寸或比例；按钮加载时保留原标签占位，不因图标与文字替换产生宽度跳动。
- 弹窗与抽屉的正文滚动，标题和底部操作不参与正文滚动。使用动态视口单位，窄屏保留边距。
- 页面不是一组嵌套卡片；业务区域优先使用分隔线、列表、表格与明确层级。

## 4. 组件契约

### Button / IconButton

`variant` 支持 primary、secondary、danger、ghost；`loading` 自动禁用点击并设置 `aria-busy`，保留原尺寸。默认 `type="button"`，提交按钮必须显式设置 submit。IconButton 强制传入 label，生成可访问名称与 title 提示。

按钮禁用只能阻止 UI 操作，业务提交仍必须用同步锁/请求状态防重复；写接口的幂等由业务层负责。危险确认默认聚焦取消或继续编辑，不能默认聚焦危险动作。

### FormField

通过 render prop 把 id、required、aria-invalid、aria-describedby 传给单个原生控件，不可丢弃这些属性。标签、提示与错误正确关联。必填、长度与格式由控件和业务校验实现；FormField 不负责请求或值管理。

```tsx
<FormField label="渠道名称" required error={error}>
  {props => <input {...props} value={name} onChange={e => setName(e.target.value)} />}
</FormField>
```

保存失败保留所有草稿和已选附件。字段错误靠近字段，请求错误放在当前操作区域；避免用短暂通知作为唯一失败反馈。成功前不能清空草稿或关闭表单。

### Dialog / Drawer

使用浏览器原生 `<dialog>.showModal()` 的 top layer 和背景 inert，统一补充 Tab 循环和关闭后焦点恢复；不自建数字 z-index 堆栈。`initialFocus` 应传入稳定 ref，优先业务首字段或安全操作。

- `open` 是受控状态；所有用户关闭意图通过 `onRequestClose(reason)`，reason 为 escape、backdrop、close-button。
- 默认禁止遮罩关闭；只读抽屉可显式开启 `dismissOnBackdrop`。脏表单由调用方统一拦截关闭请求和取消按钮，弹出放弃确认。
- `busy` 阻止 Escape/关闭/遮罩关闭，并禁用正文 fieldset。底部由调用方传入，必须自行禁用取消和提交按钮。
- 请求失败提示必须在当前操作区可见；长表单优先放在固定底部操作区，不能藏在滚动正文末尾。
- 嵌套弹窗只由最上层响应 Escape；关闭子层后回到父层，关闭父层后回到原触发器。
- 不允许调用方在保存中强制关闭或卸载；必须在结果明确后更新 open。跳转/卸载时请求取消与结果忽略由业务负责。

### Popover

使用原生 `popover="auto"`、popovertarget 和 top layer；支持 Escape、外部点击关闭、aria-expanded，同步滚动/窗口尺寸与 visualViewport 变化后的位置。浮层在视口边缘翻转并限制宽高。

组件是普通内容区域，不伪装成 menu 或 listbox。菜单、组合框等需要方向键语义的控件应另行实现专用组件，不能直接套用本组件宣称符合其交互规范。弹窗内的 Popover 必须作为弹窗子树渲染。

### AsyncState

| status | 行为 |
| --- | --- |
| loading | 首次加载，无业务内容，显示加载状态 |
| ready | 显示内容 |
| refreshing | 保留内容，显示更新状态 |
| empty | 显示真实空记录，不冒充加载失败 |
| error | 显示明确失败，可传 onRetry |
| partial | 保留已有内容，显示部分失败和重试 |

消息文案可覆盖；组件不发请求、不自动重试。保留内容不等于允许重复写操作，业务需单独控制权限与可用状态。

## 5. 会话业务要求（后续迁移验收）

以下是业务层必须满足的规则，不由基础组件自动提供：

- 草稿按会话、消息模式隔离；切换时旧请求不得覆盖新会话，使用取消或请求身份校验。
- 阅读历史时普通入站消息不强制滚到底部；首次进入、主动发送及跳到最新的策略分别定义。
- 加载历史保留视觉锚点；媒体加载应预留比例，避免消息跳动。
- 发送目标与确认内容在上传、翻译、发送过程中冻结；失败重试沿用幂等 ID。
- 离线、排队、失败、不确定、已发送和已送达不得混为一谈；不确定结果不能自动重复发送。

## 6. 验收与发布门槛

基础命令：`npm run lint`、`npm test`、`npm run test:ui`。浏览器脚本需要本机可解析 Playwright 和已安装 Chromium，沿用仓库现有可选浏览器测试方式，不新增生产依赖。截图输出到忽略目录 `outputs/ui-lab/`。

自动验收覆盖：1440×1000、390×844、320×568、844×390；状态切换、失败重试、草稿保留、保存中锁定、嵌套 Escape、焦点回归、Tab 循环、抽屉、浮层和正文滚动。额外以 720×500 的 CSS 视口检查密度重排；这不等价于真实浏览器 200% 缩放。

发布前还必须人工检查真实 200% 浏览器缩放、手机软键盘、长翻译文本、Chrome/Edge/Firefox/Safari 的实际交互与辅助技术。原生 dialog/popover 需要支持这些 API 的现代浏览器；本轮不提供旧版浏览器 polyfill，不能把 Chromium 测试当成全浏览器兼容保证。

评审清单：

- [ ] 复用基础组件，例外有具体原因。
- [ ] 无页面横向溢出、按钮遮挡、无法到达的主要操作。
- [ ] 加载、空、失败、部分失败、成功均有明确行为。
- [ ] Tab、Shift+Tab、Escape、焦点恢复与嵌套浮层正确。
- [ ] 失败保留输入，保存不重复，未保存退出可取消。
- [ ] 改公共组件时同步验收页和测试；迁移业务模块时运行其原有回归。
- [ ] README 和标准文档与实际实现一致，测试局限如实记录。

## 7. 渐进迁移与问题分级

问题记录至少包含：页面/入口、角色与渠道类型、复现步骤、视口与缩放、预期/实际、截图和回归用例。

P0：误发、错对象、数据丢失或权限泄露，阻止上线。P1：关键操作不可达、无法退出、反复提交等操作阻断。P2：状态歧义、布局跳动、键盘不可达。P3：不影响操作的视觉偏差。

迁移顺序：简单设置表单与复杂编辑弹窗试点 → 会话主流程 → 其余模块。每次限定模块和行为范围，迁移前记录原流程，替换后删除明确废弃的旧样式，避免追加覆盖；不得借治理擅自更换框架、核心依赖或业务协议。
