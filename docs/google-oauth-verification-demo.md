# Google OAuth 验证演示视频规划

本文供 RelayDesk 后续提交 Gmail 受限权限验证时准备录屏使用，不表示已提交或通过验证。只做视频与材料规划，不上传视频、不替部署方提交审核。是否需要验证，先参阅 [README 的 Google OAuth 说明](../README.md#长期使用发布到生产环境与-google-验证)。

## 目标与适用范围

演示从真实应用发起 Google 授权，到标签内新邮件进入客服会话的完整过程，说明 `https://www.googleapis.com/auth/gmail.readonly` 如何支撑实际功能。视频、Data Access 用途说明、公开首页和隐私政策必须描述同一部署及真实数据流。

Google 官方要求演示完整 OAuth 流程、英文同意屏幕及请求权限的实际用途；提交时以控制台和审核团队的最新要求为准。下文的时长、测试数据、镜头安排和旁白均为本项目的制作建议，不是 Google 强制格式或通过审核的保证。视频也不能替代适用的品牌验证或安全评估。

## 录制前准备清单

- 使用独立浏览器配置和专用测试账号，关闭通知、密码管理器弹窗、无关标签页；提前登录以避免录入密码或验证码。
- 使用可用的演示部署，确认 API、Worker、数据库和附件存储正常。不要只录模拟界面或预先放入的会话数据。
- 核对只请求实际需要的 `gmail.readonly`；不要为视频扩大权限、放开后台访问或修改生产授权用户范围。
- 若使用独立测试项目或预发布环境，记录它与送审项目的对应关系，并按控制台及审核人员要求确认是否可用；不要把不同项目的品牌和权限混在一起。
- 在 Gmail 中提前配置过滤器，将业务收件地址匹配的邮件标记为 `RelayDesk-Demo`；筛选条件可参考 README 的域名过滤器说明。过滤器由用户在 Gmail 配置，不是 RelayDesk 自动创建。
- 可准备一封标签内旧邮件，主题 `RD-DEMO-OLD-01`，用于解释首次连接不回填。勾选“同时将此过滤器应用于匹配的会话”只会给历史邮件打标签，不会令 RelayDesk 自动回填。
- 准备一个独立发件账号和无敏感信息的测试附件，例如含“仅供 OAuth 演示”字样的 PNG；不要使用真实合同、身份证件或客户文件。
- 先彩排一次，确认管理员界面、授权、标签选择、立即同步、正文和附件均可实际操作。正式录制重新使用唯一主题，避免把彩排数据当成新同步结果。
- 建议 1920 × 1080 录制、浏览器缩放约 100%；保证地址栏、应用名称、权限说明和邮件内容可读。建议总长约 5–7 分钟，按真实等待时间调整。

## 测试邮件脚本

正式录制给每次演示加唯一后缀，例如 `20261117-A`；下面的主题只是模板，时间后缀使用实际录制日期。

| 编号 | 主题与内容 | 到达时间与标签 | 预期结果 |
| --- | --- | --- | --- |
| OLD | `RD-DEMO-OLD-01-<本次后缀>`；普通测试正文 | 标签保存之前已存在，带目标标签 | 不自动回填；作为可选补充镜头，不替代新邮件演示 |
| IN | `RD-DEMO-IN-01-<本次后缀>`；正文“请确认测试订单 DEMO-001 的交期”，附测试 PNG | 标签保存成功之后发送并到达，带目标标签 | 导入映射渠道，会话中显示正文及附件 |
| OUT | `RD-DEMO-OUT-01-<本次后缀>`；正文“标签外对照，不应归档” | 同期到达，但不带目标标签 | Gmail 可见，完成同步后 RelayDesk 不导入 |
| REPEAT | 不另发邮件，再执行一次同步 | 保持 IN 邮件和标签不变 | IN 邮件不重复归档 |

对照邮件不要发到会被同一规则打标签的地址；发送后先在 Gmail 核对实际标签。若过滤器按整个业务域名匹配，应使用另一个不匹配该域名的收件地址或直接发到测试 Gmail。确保发件账号、转发路径及其他 Gmail 规则不会意外给 OUT 打上目标标签。

“没有导入”的证明需建立在邮件已到达和同步已完成的基础上；不能只展示一个空列表。演示时展示渠道筛选及唯一主题检索，避免邮件被其他筛选条件隐藏。若出现同步错误，先解决再重录，不把未执行同步当成筛选成功。

## 权限与数据流讲解要点

- Google 授权范围是 Gmail 只读访问；`RelayDesk-Demo` 仅限制本应用的同步选择，不是仅能读取该标签的 OAuth scope。
- 邮件原文、正文和附件用于归档、联系人匹配及会话处理，因此只读取元数据不足以完成现有功能。
- 数据流为 Gmail → 部署方 API / Worker → 数据库及附件对象存储 → 获授权坐席；Google OAuth 不等于获得了邮件发送 Provider 的授权。
- Gmail 收件集成不自动创建过滤器、不修改 Gmail 标签、不删除 Gmail 原邮件，也不通过 Gmail API 发信。
- 首次连接、更改标签或重新授权会重建同步起点；不要为了展示历史内容而宣称自动回填。
- 仅在实际开启相关功能时演示 AI 或其他第三方处理，并在用途说明、视频和隐私政策中保持一致；不得声称未验证的加密、自动清理或第三方数据不留存能力。
- 撤销 Google 授权不等于删除已归档数据。可以展示 Google 账号的第三方应用连接管理入口；实际撤销作为可选尾声，放在收件演示之后，只对测试账号操作，并说明后续收件将停止。

- [ ] 视频中的品牌、域名、授权项目、申请权限与本次送审材料一致；录制日和演示环境已记录。
- [ ] 展示了完整 OAuth 流程及英文同意屏幕，权限文字可读，没有跳过关键授权步骤。
- [ ] 展示了应用中请求权限的真实入口，以及授权后实际读取标签、邮件正文和附件的用途。
- [ ] 标签内新邮件成功入库；标签外对照及重复同步检查有可核对的结果，没有同步错误。
- [ ] 实际开启的权限相关功能均按审核要求覆盖；新增功能或 scope 后重新评估视频是否需要更新。
- [ ] 公共页面与实际数据流、第三方处理、保留和删除能力一致；没有虚构审核通过或仅标签授权。
- [ ] 没有真实客户内容、密钥、令牌、密码、验证码、授权码；如脱敏，不遮挡应用品牌、权限及必要操作证据。
- [ ] 按当前页面要求上传 YouTube；建议设为“不公开列出（Unlisted）”并验证审核人员无需额外授权即可观看，不设置为仅本人可看的私享视频。
- [ ] 用未登录窗口检查视频链接、画质、字幕及公共页面可访问性，再将实际链接填入 Data Access。
- [ ] 在 Verification Center 核对是否真正提交，而不只是保存草稿；按审核反馈补充材料，提交后保持链接可访问。

不公开列出的视频仍可被持有链接的人观看和转发，不能当作机密存储。若审核要求测试账号或演示访问方式，按其指定渠道单独提供，不把密码放进视频或公开文档。后续流程还可能要求额外材料或安全评估，本规划不代替 Google 审核结论。

## 常见录制问题

| 问题 | 排查或处理 |
| --- | --- |
| 授权账号不匹配 | 填写实际授权 Gmail 地址；Cloudflare 域名收件地址通常不是 Gmail 身份，不能混填 |
| 授权返回失败 | 核对 Gmail API、客户端配置、完整回调地址和服务环境；不要靠剪辑隐藏失败 |
| 旧邮件不导入 | 当前设计不回填；保存标签后发送全新的 IN 邮件 |
| Gmail 搜得到但标签页没有邮件 | 核对过滤器是否执行打标签；历史邮件需应用规则，但历史打标签不等于系统回填 |
| OUT 也被导入 | 检查实际标签和其他规则；核对测试渠道是否还有其他收件入口，不掩盖结果 |
| 视频里没有同意屏幕 | 彩排并重新发起真实测试授权；不要以已连接截图代替完整 OAuth 流程 |
| 需要展示源代码或后台配置 | 只展示审核所需的非敏感内容；不要打开环境变量、完整请求日志或含密钥的配置页 |
