# LiveChat 会话记录邮件模板

## 配置入口

系统设置 → LiveChat → 新增／编辑渠道 → 会话记录邮件模板。

- 邮件主题：1–200 字符，禁止换行。
- 邮件正文：1–20,000 字符，必须包含 `{{messages}}`。
- 单条消息格式：1–5,000 字符，必须包含 `{{message.body}}`；默认同时包含附件数组。
- 客服部门：最多 100 字符，为当前渠道的部门显示名，不是新的组织或权限模型。
- 恢复默认模板只修改当前草稿，保存渠道后才生效。保存失败保留输入。
- 预览使用固定虚构客户及消息，不读取会话、客户或 Provider API。渠道名称、Logo 和部门使用当前草稿。

模板为纯文本，不支持 HTML、脚本、条件、循环指令或递归变量替换。正文中的聊天记录数组由系统遍历，每条使用“单条消息格式”并自动添加实际发送者与时间、左右对齐样式。支持现有渠道语言配置，但模板正文不会自动翻译。

## 变量

| 变量 | 取值 | 可用位置 |
| --- | --- | --- |
| `{{visitor.name}}` | 原访客客户资料中的姓名，无姓名时为 Visitor | 主题、正文、单条消息 |
| `{{visitor.email}}` | 当前发送目标的主邮箱 | 主题、正文、单条消息 |
| `{{conversation.id}}` | 原访客对话 ID，不是合并主会话 ID | 主题、正文、单条消息 |
| `{{conversation.startedAt}}` | 对话创建时间，UTC ISO 8601 | 主题、正文、单条消息 |
| `{{conversation.endedAt}}` | 已关闭对话的结束时间；访客结束并发送时为本次结束快照时间；后台导出进行中的对话时为空 | 主题、正文、单条消息 |
| `{{conversation.duration}}` | 创建至结束或导出快照的时长，HH:MM:SS，小时可超过 24 | 主题、正文、单条消息 |
| `{{agent.name}}` | 对话当前认领客服姓名，未认领时为空 | 主题、正文、单条消息 |
| `{{department.name}}` | 渠道模板中的客服部门，未填写时为空 | 主题、正文、单条消息 |
| `{{messages}}` | 原对话消息数组，按时间和消息 ID 稳定排序并渲染 | 正文 |
| `{{message.body}}` | 当前消息原文或媒体说明；无正文且无附件时显示 [Message] | 单条消息 |
| `{{message.time}}` | 当前消息的 UTC ISO 8601 时间；默认消息头也会显示时间 | 单条消息 |
| `{{message.attachments}}` | 当前消息附件文件名数组，逐行显示 [Attachment: 文件名]，无附件时为空 | 单条消息 |
| `{{channel.name}}` | 原访客渠道名称 | 主题、正文、单条消息 |
| `{{channel.logo}}` | 原渠道自定义图标：HTML 邮件显示固定尺寸图片，纯文本邮件显示 URL；未设置时为空 | 正文 |

当前 LiveChat 每条消息最多关联一个媒体文件，因此附件数组通常为零或一个元素；渲染器支持多个文件名。不附带文件二进制、不生成免鉴权下载链接、不泄露对象存储 key。Logo 仅接受不含用户名密码的 HTTPS 地址，收件客户端可能阻止远程图片。

对话重新开启仍沿用原对话创建时间及其完整聊天历史，不将每次重新开启视为独立 transcript 会话。消息头中的访客姓名来自客户资料；客服优先取该条消息的实际发送人，其次为当前认领客服、渠道名称或 Support。AI 或自动消息未关联真实坐席时不会虚构坐席。

## 数据与安全边界

只导出原访客对话的入站及已发布出站消息，不包含 queued、failed、uncertain 等未确认出站消息、邮件气泡、合并时间线其他客户、内部备注或共享邮件档案。保留现有权限、Provider 路由、幂等请求及事务回滚机制。

所有输入作为文本转义，不递归解释客户消息中的变量；未知变量、使用位置错误、括号不完整、缺少消息数组或消息正文会阻止保存。主题变量中的换行被移除，最终主题最多 200 字符；渲染结果为空时使用默认主题。

## API 与部署

管理员现有渠道 POST／PUT 接口新增可选 `transcriptTemplate` 对象：

```json
{
  "subject": "{{channel.name}} - Chat transcript",
  "body": "{{channel.logo}}\nHello {{visitor.name}},\n{{department.name}}\n{{messages}}",
  "message": "{{message.body}}\n{{message.attachments}}",
  "departmentName": "Sales"
}
```

管理员渠道列表以 `transcript_template` 返回保存值；公开窗口配置不返回模板或部门字段。PUT 不提交该字段时保留原值，显式提交 `null` 时恢复系统默认。新旧渠道未自定义时使用共享的默认模板，不新增依赖。

API／Worker 启动执行 `115_livechat_transcript_template.sql`，新增可空 JSONB 列；重复执行不覆盖已有模板。需要同步部署工作台、API 和 Worker 并重启，不补发历史邮件，也不改写已入队快照。新安装仍按 README 执行完整数据库初始化。

测试包括变量替换、空数组、多个附件名、HTML／Logo／邮件头安全、模板校验、渠道保存与旧请求兼容、公开配置隔离、权限、发送快照与两种结束时间语义。浏览器回归覆盖 1440×1000、390×844、320×568、844×390 的变量插入、错误草稿保留、回填、恢复默认及预览布局。真实数据库迁移、邮件投递和 Outlook／Gmail 等客户端兼容需在部署环境另行验收。
